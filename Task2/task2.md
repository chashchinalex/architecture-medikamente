# Целевая архитектура системы «Medikamente» (To-Be)

## Применение принципов Privacy by Design

### 1. Проактивный подход
- Внедрение механизмов раннего выявления и управления рисками  
- Автоматическая классификация поступающих данных

### 2. Конфиденциальность по умолчанию
- Сбор только минимально необходимой информации  
- Использование RBAC/ABAC для ограничения доступа  
- Обязательное шифрование всех данных

### 3. Конфиденциальность в проектировании
- Централизованное управление идентификацией и доступами  
- API Gateway как единая точка входа  
- Сквозное шифрование данных

### 4. Полная функциональность
- Удобный и защищённый портал пациента  
- Высокая производительность системы при активных мерах защиты

### 5. Комплексная безопасность на всём жизненном цикле
- Шифрование данных при хранении и передаче  
- Политики хранения и безопасного удаления  
- Аудит всех операций с данными

### 6. Прозрачность
- Панель управления конфиденциальностью для пациентов  
- Детальное логирование операций  
- Возможность формирования отчётности для регуляторов

### 7. Уважение к пользователям
- Управление пользовательскими согласиями  
- Право на удаление данных  
- Простые и понятные формы согласия

# Target Architecture Layers

## **1. Security & Privacy Layer**

| Компонент | Назначение | Принципы PbD |
|-----------|------------|--------------|
| **IAM Service** | Управление идентификацией и доступами (RBAC/ABAC) | 2, 3 |
| **API Gateway** | Единая точка входа, аутентификация, ограничение нагрузки | 3, 5 |
| **Encryption Service** | Шифрование данных, управление ключами | 3, 5 |
| **Audit Service** | Логирование действий с данными | 5, 6 |
| **Consent Management** | Управление согласиями пациентов | 2, 7 |
| **Data Classification** | Автоматическая категоризация данных | 1, 3 |

---

## **2. Business Services Layer**

| Компонент | Назначение |
|-----------|------------|
| **Patient Portal** | Личный кабинет пациента: записи, история, результаты |
| **Reception Portal** | Интерфейс для сотрудников ресепшена |
| **Medical Records Service** | Управление медицинскими картами |
| **Appointment Service** | Управление расписанием и записями |
| **Payment Gateway** | Обработка платежей (PCI DSS) |
| **Notification Service** | Уведомления (SMS, email, push) |
| **Laboratory Integration** | Интеграция с лабораторией через API |
| **CRM** | Управление взаимодействиями с клиентами |

---

## **3. Analytics Layer**

| Компонент | Назначение | Защитные меры |
|-----------|------------|----------------|
| **Data Lake** | Централизованное хранилище сырых данных | Шифрование, контроль доступа |
| **Anonymization Service** | Обезличивание данных для аналитики | Псевдонимизация, k-anonymity |
| **BI Platform** | Отчёты, аналитика, дашборды | Только агрегированные данные |

---

## **4. Data Storage Layer**

| Компонент | Данные | Защита |
|-----------|--------|--------|
| **Patient DB** | Персональные данные (PII) | AES-256, TDE |
| **Medical DB** | Медицинские данные (PHI) | Изолированный контур, AES-256 |
| **Operational DB** | Операционные данные | Шифрование |
| **Audit DB** | Логи аудита | Неизменяемое хранилище |

# Диаграмма контекста C4 (To-Be)

## Внешние акторы
- **Пациент** — через портал или мобильное приложение  
- **Врач**  
- **Администратор** (ресепшен)  
- **Бухгалтер**  
- **Кладовщик**

## Внешние системы
- **Лаборатория** — обмен данными через API  
- **Платёжный провайдер**  
- **Сервис SMS/Push уведомлений**

## Внутренние системы
- **Medikamente Platform**  
  - API Gateway  
  - IAM Service  
  - Patient Portal  
  - Reception Portal  
  - Medical Records  
  - Appointments  
  - Payments  
  - Notifications  

- **Privacy & Security Services**  
  - Encryption Service  
  - Audit Service  
  - Consent Management  
  - Data Classification  

- **Analytics Platform**  
  - Data Lake  
  - Anonymization  
  - BI/Reporting  

- **Legacy Systems**  
  - 1С Бухгалтерия  
  - 1С Торговля и склад  
  - ККМ
