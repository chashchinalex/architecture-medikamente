# Задание 4. Оценка узких мест при миграции. Диаграмма Исикавы

## 1. Основные процессы и компоненты, затрагиваемые миграцией
- Базы данных (PostgreSQL, файловый сервер 1С, Excel)
- Бизнес-логика монолита и её перенос в микросервисы
- Интеграции с 1С, лабораторией, ККМ
- Коммуникации между сервисами (API, сеть)
- Клиентский портал и мобильное приложение
- Системы безопасности (RBAC, токены)
- Серверная инфраструктура (Windows Server, on-prem)
- Бэкап и восстановление

---

## 2. Диаграмма Исикавы (для переноса в draw.io)

### **Категории и потенциальные причины узких мест**

### **1. Инфраструктура**
- Ограниченная пропускная способность сети
- Единый сервер как точка отказа
- Недостаток ресурсов для контейнеризации
- Отсутствие оркестрации (Kubernetes)

### **2. Программное обеспечение**
- Монолитный код → сложно выделить домены
- Неподдерживаемые библиотеки
- Сложности обратной совместимости API
- Низкое покрытие тестами

### **3. Интеграции**
- 1С в файловом режиме → недостаточная производительность
- Отсутствие API у лаборатории
- Зависимость от Exchange Server
- Нестабильные форматы данных Excel

### **4. Данные**
- Разнородные источники: Excel, PDF, JPG
- Отсутствие нормализации и схем
- Риск рассинхронизации между системами
- Большой объём исторических данных для миграции

### **5. Персонал**
- Недостаточный опыт микросервисной архитектуры
- Ограниченная экспертиза в Kubernetes
- Сопротивление изменениям
- Недостаток DevOps-навыков

### **6. Процессы**
- Нет CI/CD
- Нечёткое определение границ сервисов
- Ручные операции → ошибки при миграции
- Отсутствие автоматизированного тестирования

---

## 3. Рекомендации и меры по устранению узких мест

### **Высокий приоритет**
1. Внедрение CI/CD и автоматизированного тестирования  
2. Создание API-шлюза для упорядочивания интеграций  
3. Миграция 1С в клиент-серверный режим  
4. Сегментация данных и пересмотр моделей хранения  
5. Внедрение Kubernetes и контейнеризации  
6. Обучение персонала (DevOps, микросервисы)  

### **Средний приоритет**
1. Перевод Exchange в облако или отказ от него  
2. Создание ETL-конвейеров для переноса данных  
3. Введение единой схемы данных (Data Governance)  

### **Низкий приоритет**
1. Оптимизация внутренних процессов после запуска микросервисов  
2. Рефакторинг части старого кода для совместимости  

---

## 4. Итоговый отчёт (краткое описание)

Миграция затрагивает инфраструктуру, данные, интеграции, бизнес-процессы и персонал. Основные риски включают недостаток ресурсов on-prem, сложности разбиения монолита, отсутствие автоматизации, слабые интеграционные контуры и неподготовленность персонала. Предложенные меры направлены на обеспечение стабильной миграции: переход на Kubernetes, API-ориентированную архитектуру, CI/CD, переход 1С в клиент-серверный режим и обучение сотрудников. Диаграмма Исикавы позволяет визуализировать взаимосвязи проблем и формирует основу для плана миграции.
